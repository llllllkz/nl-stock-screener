# AI 使用与验证记录

## 使用了哪些 AI 工具

- **Kimi Work（Moonshot AI）**：承担本产品的主要设计与编码工作，包括架构设计、数据拉取脚本、解析层/引擎/前端实现、测试与文档撰写。
- **iFinD 数据插件（agent-gw）**：由 AI 调用，提供 A 股行情与财务指标真实数据。

## AI 参与了哪些环节

| 环节 | AI 的工作 | 人工/确定性校验 |
| --- | --- | --- |
| 方案设计 | 提出「AI 翻译 + 确定性引擎裁决 + 缺失三分」架构与职责边界 | 对照题目要求逐条核对 |
| 数据获取 | 编写批量取数脚本并调用 iFinD 接口 | 检查返回行数、日期窗口、失败重试记录（首轮 9 批因 Windows 控制台编码失败，修复后全部成功，0 数据缺失重拉） |
| 指标计算 | 由 `build_snapshot.py` 确定性计算（波动率/回撤/PE/PB） | 单元测试覆盖派生指标；抽查贵州茅台等个股数值与行情软件口径一致 |
| 意图解析 | 设计模糊词 → 条件的映射与澄清选项 | 候选人对每个映射的默认阈值进行了人工复核（如「估值合理」默认 PE 0–30） |
| 前端实现 | AI 生成六步主链路 UI | 浏览器实操验证主链路、合规示例、缺失样本展示 |

## AI 犯的错与候选人的修正（验证记录）

1. **子进程编码错误**：首轮批量取数在 Windows GBK 控制台解码失败导致 9 个批次误判为失败。
   修正：改为以「CSV 文件实际落盘」为成功判据并强制 UTF-8 解码，重跑后 5 组数据全部 0 失败。
2. **敏感性分析方向颠倒**：最大回撤（负值阈值）按「×0.8 = 放松」计算时方向反了（−20 → −16 实为收紧）。
   验证方式：浏览器实操发现「放松」后入选数不增反减。
   修正：改为按区间几何意义扩/缩，并用实际入选数反向校验标签方向；补充单元测试锁定（负值阈值用例）。
3. **「行情截至」文案截断**：对口径字符串做 `slice(-10)` 导致显示为「-30（前复权日线）」。
   修正：改为显式日期文案。
4. **无条件时误标「排除」**：全部条件停用时 49 只股票被归入「排除」栏，语义错误。
   修正：无启用条件时一律归入「无法判定」并提示「不构成筛选结论」。
5. **阈值为 0 时敏感性退化**：「同比 ≥ 0」按百分比缩放后仍是 0，放松/收紧无变化。
   修正：阈值为 0 时改用 ±5 的绝对步长。
6. **样本数文案不一致**：页脚写 48 只，实际股票池 49 只。修正为 49 并同步快照元数据。

## 关键数字的可追溯性

- 每只股票卡片上的 PE/PB/ROE/同比/波动率/回撤均可回到 `data_raw/` 中对应 iFinD 原始 CSV；
  计算逻辑（含口径注释）在 `build_snapshot.py` 与 `app/src/engine/metrics.ts`。
- 示例：平安银行入选理由「PE 5.59 ∈ [0,30]」= 2026-09-30 收盘价 11.57 元 ÷ 2025 年报基本 EPS（见 `data_raw/price_*.csv` 与 `data_raw/prof_fy25_*.csv`）。
