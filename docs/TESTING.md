# 测试说明

## 一、自动化测试（`cd app && npm test`，vitest，14 例全部通过）

### 主链路
- 「经营改善、估值合理、走势相对稳定」→ 产出 3 个澄清项 + ≥5 条默认条件，且每条条件可追溯来源表述；
- 澄清选项切换后条件随之替换（如「估值合理」切换到严格档 → PE 0–15）；
- 无法识别的输入不产出条件并给出提示。

### 数据缺失 / 接口异常
- 关键字段缺失（如亏损股 PE=null）→ 状态为 `unknown`（无法判定），理由明确标注「缺失」，**绝不静默当作不通过**；
- 派生指标 profitAccel 在任一基数缺失时返回 null 并走缺失分支（由指标注册表保证，配合缺失用例覆盖）；
- 取数脚本对失败批次最多重试 3 次并以落盘文件为成功判据（首轮 9 批失败→修复后 0 失败，见 AI_USAGE.md）。

### 冲突与极端边界
- 同一指标区间无交集（PE ≤15 与 PE ≥30）→ 识别为逻辑互斥并给出建议；
- 结果为空 → 定位「约束最强」条件（逐条停用比较入选数）并给出放松建议；
- 全部条件停用 → 不产出「入选」结论；
- 敏感性：放松约束入选数增加、收紧减少；**负值阈值（最大回撤）方向不颠倒**；阈值为 0 时使用绝对步长。

### 合规边界
- 「高股息」→ 标记为不支持意图并说明原因，不生成伪条件；
- 「必涨」「推荐买入」→ 触发 ≥2 条合规提示（收益承诺类 + 买卖建议类），且不输出任何买卖建议。
